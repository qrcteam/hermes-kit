Whose keyboard is this?

Every command block on this page is stamped with the machine it belongs to. Phase 00 is the only thing you run on your own Mac. From the moment you have remote control, everything — clone, Docker, vault, keys, container, crons — happens on hers, in a Terminal window on her screen.

The trap: the kit lands at ~/Documents/Projects/hermes on both machines, so the commands look identical either side. Run phase 04 or 05 on your own Mac by mistake and you overwrite your own ~/.hermes/.env, your own Pinecone key, and start a second gateway fighting your own bot for its token. Before pasting anything below phase 00, glance at the window title and confirm it says her name.

00

Before you dial

~15 min · your machine

00.1Pull the kit and read her record

You are about to type these commands on someone else's computer. Have the current version in front of you, not last week's.

Your Mac
cd ~/Documents/Projects/hermes && git pull
open docs/02-runbook-mac.md people/laurie.md docs/06-troubleshooting.md

00.2Confirm the six accounts landed

She was sent beautiful-possibilities.com/kit/install/start ahead of today. Text her the morning of and ask for a straight yes on each: Telegram, model subscription, GitHub, Pinecone, OpenRouter credit, Obsidian downloaded.

Why this can't wait until you're on the call: every one of these has an email-confirmation step, and a Pinecone signup discovered at minute forty is twenty minutes of two people watching an inbox.

00.3Decide her buckets — or plan to decide them with her

Four or five folders that her whole life sorts into, in her words. They get created at step 04.2 and renaming them later is a chore. Doug's are project-shaped (projects · clients · learning · personal); Mazíx's are life-area-shaped (creative · qrc-brand · health · home · personal). Laurie's are not decided yet.

Open decision

If you haven't got them, ask her in the first ten minutes of the call — before any typing — and write them into people/laurie.md as you go. Don't guess them on her behalf; the bucket names are the first thing she'll see in Obsidian and they should sound like her.

01

Open the call — before any typing

~10 min

01.1Say the boundary sentence out loud

Her vault repo starts in qrcteam so you can clone and fix it without a screen-share during the weeks when things actually break, and it transfers to her own GitHub once the install is stable. That arrangement is only honest if she hears it.

Say something close to: "Her memory lives in a private repo on my organisation's GitHub for now, which means I can read her notes. I'd rather say that than have her assume otherwise. It moves to her account the moment this is stable, and it keeps working through the move."

01.2Set the two Mac facts

Her assistant can only answer while her Mac is awake. Do this first — a Mac that sleeps also drops your remote session mid-install.

  • System Settings → Lock Screen → display off is fine, sleep is not.
  • On a laptop, check the same under battery/power and leave it plugged in.

01.3Book the 45 minutes for the interview

Everything in phases 02–05 is plumbing. Phase 06 is the product. If today's window is under two and a half hours, agree now that the interview moves to a second call rather than getting compressed into fifteen rushed minutes.

02

Get on her Mac

~15 min

Not covered by the kit. Mazíx's install was on-site; the runbook has never had a remote-access step. This is a recommendation, not a proven path — budget extra time the first time.

02.1Screen share with remote control

Recommended default: Zoom. She shares her screen, you click Request remote control, she approves once. macOS will make her grant Zoom Screen Recording and Accessibility permission in System Settings → Privacy & Security — that prompt appears the first time and needs her password.

Fallback if Zoom fights you: macOS Screen Sharing over the Messages app (both on iMessage, Details → share screen → ask to control).

What remote control cannot do for you: type her passwords, approve an admin prompt, scan a QR code, or log into her accounts. Plan for her hands on the keyboard at four moments — the Docker install password, the Pinecone key copy, the model login, and the Telegram bot creation on her phone.

02.2Command Line Tools and Homebrew

A stock Mac has neither git nor brew. The runbook assumes both. Install them before anything else — the first one opens a GUI dialog she has to accept.

Her Mac
# pops a dialog — she clicks Install, then wait it out
xcode-select --install

# Homebrew — asks for HER admin password
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Apple Silicon only: put brew on PATH for this shell and future ones
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

git --version && brew --version
03

Clone the kit, install the software

~20 min · mostly waiting

03.1Clone hermes-kit to the path the runbook expects

Every command in the runbook refers to ~/Documents/Projects/hermes. Clone it exactly there and you never have to translate a path live.

Her Mac
mkdir -p ~/Documents/Projects
git clone https://github.com/qrcteam/hermes-kit.git ~/Documents/Projects/hermes
ls ~/Documents/Projects/hermes/templates
Yes, Documents is fine for the kit. The "never Desktop, Documents or Downloads" rule is about the vault — macOS blocks background jobs from those folders, and the promoter is a background job. The kit is only ever read by you, by hand, from a terminal you opened. Her vault still goes to ~/Memory and nowhere else.

It's a private repo, so git clone will ask for GitHub credentials. Easiest path is to install the GitHub CLI now — you need it in a minute anyway:

Her Mac
brew install gh
gh auth login   # HTTPS · browser flow · SHE logs in with her account

03.2Docker Desktop and Obsidian

Her Mac
brew install --cask docker
brew install --cask obsidian

Open Docker Desktop once and let it finish starting. It asks for her admin password and shows a licence agreement — her hands. Nothing below works until it's running.

Her Mac
docker --version && docker ps
04

Her bot, her vault, her index

~25 min

04.1Make the Telegram bot — on her phone

  1. Message @BotFather → /newbot
  2. Name it something she'll recognise — "Laurie's Assistant"
  3. Username must end in bot — e.g. lauries_memory_bot
  4. Copy the token (8123456789:AAF…) — treat it like a password
  5. Message @userinfobot → copy the numeric user ID it replies with

That numeric ID is the only thing between a stranger and her memory. Read it back to her digit by digit before pasting it.

Ask now whether she wants WhatsApp too — self-chat mode, she messages herself and the agent answers in that thread. If yes, get her number as 15551234567. Pairing happens after the container is up.

04.2Build the vault

Replace the bucket list on the for b in … line with hers from 00.3.

Her Mac
export NAME=laurie
export VAULT=~/Memory/$NAME-vault
mkdir -p "$VAULT"

cp -R ~/Documents/Projects/hermes/templates/vault-skeleton/. "$VAULT"/
mv "$VAULT/gitignore.template" "$VAULT/.gitignore"
chmod +x "$VAULT/scripts/pinecone-sync"

# ← HER buckets, her words
for b in projects clients learning personal; do
  mkdir -p "$VAULT/wiki/topics/$b"
  sed "s/<bucket-name>/$b/g; s/<Bucket Name>/${b}/g; s/<YYYY-MM-DD>/$(date +%F)/" \
    "$VAULT/wiki/topics/_MANUAL-TEMPLATE.md" > "$VAULT/wiki/topics/$b/_manual.md"
done
rm "$VAULT/wiki/topics/_MANUAL-TEMPLATE.md"
mkdir -p "$VAULT/wiki/people" "$VAULT/wiki/reference" "$VAULT/raw/sessions"

cd "$VAULT" && git init -q -b main && git add -A \
  && git commit -qm "vault: initial skeleton for $NAME"

Then create the private remote and push. With gh already authenticated this is one command and no SSH keys:

Her Mac
cd "$VAULT"
gh repo create qrcteam/laurie-vault --private --source=. --remote=origin --push
gh repo view qrcteam/laurie-vault --json visibility

04.3Her Pinecone index

She creates the API key on her own screen and pastes it. You never keep a copy.

Her Mac
export PC_KEY=<she pastes her pinecone key>

curl -s "https://api.pinecone.io/indexes/create-for-model" \
  -H "Api-Key: $PC_KEY" -H "Content-Type: application/json" \
  -H "X-Pinecone-API-Version: 2025-04" \
  -d '{
    "name": "'"$NAME"'-vault",
    "cloud": "aws",
    "region": "us-east-1",
    "embed": { "model": "llama-text-embed-v2", "field_map": { "text": "text" } }
  }' | python3 -m json.tool

Store it in a file, then clear it from the shell:

Her Mac
mkdir -p ~/.hermes/secrets
printf '%s' "$PC_KEY" > ~/.hermes/secrets/pinecone.key
chmod 600 ~/.hermes/secrets/pinecone.key
unset PC_KEY
Why a file and not the environment: the promoter needs a key that can write to the index; the agent only ever needs to search it. Keeping it out of the agent's environment means a prompt injection can't exfiltrate a credential that could wipe her index.

04.4Configure Hermes, install the two skills

Her Mac
mkdir -p ~/.hermes/{inbox,scripts,secrets}
cp ~/Documents/Projects/hermes/templates/env.template ~/.hermes/.env
chmod 600 ~/.hermes/.env
open -e ~/.hermes/.env   # paste bot token + numeric user ID (+ WhatsApp number)

K=~/Documents/Projects/hermes/templates
cp "$K/promote.sh"      ~/.hermes/promote.sh
cp "$K/vault-health.sh" ~/.hermes/scripts/vault-health.sh
chmod +x ~/.hermes/promote.sh ~/.hermes/scripts/vault-health.sh

mkdir -p ~/.hermes/skills/note-taking/vault-capture
cp "$K/vault-capture-SKILL.md" ~/.hermes/skills/note-taking/vault-capture/SKILL.md
mkdir -p ~/.hermes/skills/note-taking/session-log
cp "$K/session-log-SKILL.md"   ~/.hermes/skills/note-taking/session-log/SKILL.md
The two skills do different halves of memory. vault-capture saves facts the moment they're said. session-log saves what she did, once, at the end of a working conversation — including where she stopped, which is the line she'll reread most. Facts alone answer "what do I know?" but never "what was I working on?"
05

Start Hermes — first reply

~20 min

05.1Run the container

Her Mac
docker run -d --name hermes --restart unless-stopped \
  -p 127.0.0.1:8642:8642 \
  --env-file ~/.hermes/.env \
  -v "$HOME/.hermes:/opt/data" \
  -v "$HOME/Memory/$NAME-vault:/vault:ro" \
  nousresearch/hermes-agent:latest

The :ro is the single most important character in this kit. It makes it impossible — not merely forbidden — for the agent to damage her memory. If you retype this line from memory later, that's the character you'll drop.

Her Mac
docker exec hermes hermes config set database.journal_mode delete
docker exec hermes hermes config set approvals.mode smart
docker exec hermes hermes config set approvals.cron_mode deny
docker restart hermes
journal_mode: delete is not a preference. SQLite's write-ahead log corrupts across a macOS Docker bind mount. Get it wrong and "database disk image is malformed" turns up in about a week.

05.2Log into her model — her hands, her account

Her Mac
docker exec -it hermes hermes model
docker exec hermes hermes status

She picks her provider and follows the device-flow link. Credentials land in ~/.hermes/auth.json — never in .env.

Laurie has OpenRouter credit, which makes this mandatory, not optional. With two provider credentials in reach and model.provider: auto, adding the OpenRouter key can flip the main model onto OpenRouter carrying the wrong model ID — a non-retryable 400, and the bot goes mute because a key was added. Pin the primary and declare the fallback explicitly.

Her Mac
# primary = whichever she actually pays for:
#   ChatGPT Plus → openai-codex     Claude Pro → anthropic
docker exec hermes hermes config set model.provider openai-codex
docker exec hermes hermes config set fallback_providers \
  '[{"provider":"openrouter","model":"anthropic/claude-sonnet-4.5"}]'
docker restart hermes
docker exec hermes hermes -z "Reply with exactly: PROVIDER-OK"

05.3She texts the bot "hello"

Do not go further until a reply comes back. If nothing does, go to docs/06-troubleshooting.md → "The bot doesn't reply", and check the two usual suspects: the Telegram cold-start wedge, and two gateways fighting over one token.

05.4WhatsApp — skip if Telegram only

Telegram must be working first; two channels failing at once is twice the diagnosis. The step everything hinges on is the config block, not the .env flag:

Her Mac
docker exec hermes hermes config get platforms.whatsapp.enabled   # want: true
docker exec -it hermes hermes whatsapp   # pair from INSIDE the container
# ~30s of dependency install that looks like a hang — wait. Then choose self-chat,
# and she scans the QR: WhatsApp → Settings → Linked Devices → Link a Device
docker restart hermes
docker logs hermes 2>&1 | grep -i whatsapp | tail -3

Worth saying out loud: the bridge emulates WhatsApp Web rather than Meta's official Business API. Fine for personal self-chat. Her business number does not go on it, and nothing outbound gets automated from it.

07

The promoter, the crons, the proof

~25 min

07.1Load the promoter and prove it runs

This is the piece that actually writes her memory.

Her Mac
sed -e "s|<USER>|$(whoami)|g" -e "s|<NAME>|$NAME|g" \
  ~/Documents/Projects/hermes/templates/com.hermeskit.vault-promote.plist \
  > ~/Library/LaunchAgents/com.hermeskit.vault-promote.plist

plutil -lint ~/Library/LaunchAgents/com.hermeskit.vault-promote.plist
launchctl unload ~/Library/LaunchAgents/com.hermeskit.vault-promote.plist 2>/dev/null
launchctl load  ~/Library/LaunchAgents/com.hermeskit.vault-promote.plist
launchctl list | grep vault-promote

Exit status 0 is what you want. 78 means a malformed plist; 1 usually means a wrong path inside it. Then run it by hand before trusting the schedule:

Her Mac
VAULT_ROOT=~/Memory/$NAME-vault \
PINECONE_INDEX=$NAME-vault \
PINECONE_STATE=~/.hermes/pinecone-state.json \
PINECONE_KEY_FILE=~/.hermes/secrets/pinecone.key \
PINECONE_SYNC=~/Memory/$NAME-vault/scripts/pinecone-sync \
bash ~/.hermes/promote.sh

cat ~/.hermes/promote-state.json

07.2Watchdog and morning digest

Her Mac
docker exec hermes hermes cron create "0 14 * * *" \
  --name vault-health --script vault-health.sh --no-agent --deliver telegram

docker exec hermes hermes cron create "0 13 * * *" \
  --name daily-digest --deliver telegram \
  "Good morning. Read /vault/wiki/topics/*/_manual.md and any notes from the last 3 days.
   Give a short briefing: what's open, what's owed, what they said they'd do. Two or three
   things, in plain sentences, not a table. If nothing needs attention, say so in one line."

docker exec hermes hermes cron list

Those hours are UTC. Mountain Time is UTC−6 in summer, so 13 = 7am. Check the timezone Laurie actually lives in before you leave.

07.3Run the verifier before the live test

Read-only. It walks the whole checklist so you don't have to hold it in your head, and every FAIL prints its own fix underneath.

Her Mac
bash ~/Documents/Projects/hermes/templates/install-verify.sh

# to let it repair the mechanical ones (idempotent, reversible, can't lose data):
bash ~/Documents/Projects/hermes/templates/install-verify.sh --fix
docker restart hermes   # only if it changed a config key
Get it green before the live test below. A failing smoke test on top of a half-finished install tells you nothing about which of the two is broken.

07.4The three smoke tests

Have her text her bot something real from her own week — the shape of the classic test is: "remember I switched the Henderson job to the Tuesday crew because Thursday's tied up on Ruiz." The agent should confirm it in plain language. Then wait 15 minutes, or run the promoter by hand again, and check all three:

Her Mac
# 1 · did the note land in the vault?
ls -la ~/Memory/$NAME-vault/wiki/topics/*/ | grep -i henderson

# 2 · is it committed and pushed?
git -C ~/Memory/$NAME-vault log --oneline -3
git -C ~/Memory/$NAME-vault status -sb

# 3 · is it findable by MEANING, not keyword?
VAULT_ROOT=~/Memory/$NAME-vault PINECONE_INDEX=$NAME-vault \
PINECONE_STATE=~/.hermes/pinecone-state.json \
PINECONE_KEY_FILE=~/.hermes/secrets/pinecone.key \
~/Memory/$NAME-vault/scripts/pinecone-sync search "who is doing the Henderson work"
If the third fails but the first two pass, her memory is safe — recall is just degraded to literal search. Fix it, but don't panic in front of her.

don't pay twice

Each of these cost real time on an earlier install. They're in the runbook and troubleshooting doc — this is the glance version for when something goes sideways while two people are watching.

01

The vault must not live in Desktop, Documents or Downloads

macOS blocks background jobs from all three, silently. ~/Memory is not blocked. This one already cost a fortnight of failed syncs.

02

Adding the OpenRouter key can mute a working bot

With provider: auto and two credentials, the main model can route to OpenRouter with the wrong model ID → non-retryable 400. Pin the primary, declare the fallback. See 05.2.

03

WHATSAPP_ENABLED=true in .env is not enough

Hermes only starts platforms listed under platforms: in config.yaml. Without it you get a setup that looks configured and never replies.

04

Pair WhatsApp from inside the container

The bridge only listens on the container's own loopback. Pairing anywhere else produces a bridge Hermes cannot reach.

05

Exactly one gateway

A native hermes gateway on the host will fight the container over the same bot token. Container only.

06

journal_mode: delete, every time

Including after any container rebuild or upgrade. SQLite's WAL corrupts across a macOS bind mount, and the failure shows up about a week later.

07

Moving the vault breaks absolute paths silently

If you relocate it later, grep for the old path in the plist, the container mount, and any script before closing the terminal.
